# Project Proposal: Saudi Dialect to Modern Standard Arabic Rewriter with a Fact-Preservation Check

NLP Applications, KAUST Academy (2026 MOI cohort). Topic 6, own project, option A. Date: 19 November 2026.

## Idea and goal

A small language model, fine-tuned with LoRA, rewrites short messages written in Saudi dialect into formal Modern Standard Arabic (MSA). A checker then confirms that every number, date, time and proper name in the message survived the rewrite.

- **Users:** customer-service and administrative staff who turn messages from the public into formal correspondence.
- **One job:** a dialect message goes in, and the same message in formal MSA comes out, with no fact changed.
- **Why fine-tune:** we expect a prompted small model to leave dialect words in place and to alter or drop details. The before-and-after comparison will test this.
- **Why local:** messages from the public should stay on the organisation's own machines.
- **Goal:** more messages rewritten correctly than the untuned model with a full prompt, and fewer released outputs with a changed fact. Numerical targets will be selected and documented before the plan review, without presenting unmeasured outcomes as results.

## Dataset

- **Training:** the multidialectal parallel Arabic corpus by Khalid Almeman (Data, 2025), which pairs MSA with five dialects including Saudi: 50,010 rows in the travel and tourism domain ([paper](https://www.mdpi.com/2306-5729/10/12/208), [data](https://doi.org/10.5281/zenodo.17776617)). The Zenodo record and the paper state CC BY 4.0; the README inside the record states a non-commercial licence, so we treat the data as non-commercial. We use the Saudi–MSA pairs. The corpus was generated by a large language model, only a sample was checked by people, and it contains almost no numbers, so we add template pairs with numbers, dates, times and codes and report both points as limitations.
- **Golden test:** 100 dialect messages, most of them containing numbers, dates, times or names, each with a reference MSA version. The examples were AI-drafted and subsequently team-approved through a 25-per-member reciprocal review according to the leader. The verified test file is prepared for its GitHub freeze commit before training. See the approval record for evidence details.
- **Separation:** a script removes every training sentence that equals, nearly equals or contains a golden sentence, then verifies that no overlap remains.

## Type of training

Supervised fine-tuning with LoRA (PEFT) of `Qwen/Qwen3-1.7B`, which is inside the 4B-parameter limit. The training data is in chat format, and the loss is computed on the answer only. Training runs on a Google Colab T4 GPU, with QLoRA (4-bit) as the fallback if memory is short. The adapter will be published on the Hugging Face Hub with a model card.

## System

The model works inside a pipeline that runs on the team's own machine. First, the tuned model, served locally by Ollama, rewrites the message into MSA. Second, a checker extracts the numbers, dates, times and Latin-script words from the original and from the rewrite and compares them, and confirms that names listed by the user are still present. Third, if they differ, the pipeline asks the model for one repair with the missing facts listed. Fourth, if the repair still fails, the output is withheld and the original message is returned with a warning, so a changed fact is never released silently. A Streamlit app with right-to-left display shows the original, the rewrite, the checker's result and a before-and-after comparison.

## Evaluation

We score three systems on the golden test: the untuned model with a full prompt, the tuned model alone, and the tuned model inside the pipeline. A rewrite counts as correct only if it passes three checks: all facts preserved (automatic), no dialect word left (word list plus review), and meaning preserved (two members judging independently). We count each error type: dropped fact, changed fact, dialect word left, meaning changed, content added, and input copied without rewriting. We also count the examples that moved from wrong to right and from right to wrong. For the full system we report the share of released outputs with a changed fact and the share of messages withheld. Ten adversarial inputs of different kinds form the safety check.
